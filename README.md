# 臻美味自助餐 記帳機器人

> 適用於小型群組的 Discord 斜線指令記帳機器人，支援多人分帳、債務結算與歸檔、關鍵字觸發回應，資料儲存於 Google Sheets。可以同時服務多個伺服器，每個伺服器的資料各自存在自己的試算表裡。

---

## 技術架構

| 項目 | 內容 |
|------|------|
| Runtime | Python 3.10+ |
| 主要套件 | discord.py 2.6+ |
| 資料儲存 | Google Sheets（gspread） |
| 圖片托管 | imgbb API |
| 美股資料 | Yahoo Finance（非官方 chart API，免金鑰） |
| 保活機制 | Flask + UptimeRobot |
| 部署平台 | Render Web Service |

---

## 安裝套件

```bash
pip install -r requirements.txt
```

`requirements.txt` 裡的版本是固定的（需要 Python 3.10 以上），避免每次部署自動抓到剛發布、可能有問題的新版。要升級時手動改版本號，先在本機測過再推上去。

## 部署步驟

### 1. 建立 Discord 機器人

1. 前往 [Discord Developer Portal](https://discord.com/developers/applications) 建立 Application
2. **Bot** 頁面開啟以下 Intent：
   - `Message Content Intent`
   - `Server Members Intent`
3. 複製 Bot Token
4. 同一頁的 **Public Bot**：想讓其他群組的管理員自己邀請這個機器人就保持開啟；只打算自己用就關掉（關掉後只有你能邀請）。開著也沒關係——別的伺服器在綁定自己的試算表之前什麼都不能做，見下方「讓其他伺服器使用」
5. **OAuth2 → URL Generator** 邀請機器人：
   - Scopes：`bot`、`applications.commands`
   - Permissions：`Send Messages`、`Read Message History`、`Manage Messages`、`Mention Everyone`、`Pin Messages`

### 2. 設定 Google Sheets API

1. 前往 [Google Cloud Console](https://console.cloud.google.com) 建立專案
2. 啟用 **Google Sheets API** 與 **Google Drive API**
3. 建立**服務帳號**，下載 JSON 金鑰
4. 建立 Google 試算表，新增以下工作表（名稱必須完全一致）：

   **expense**（未結清帳目）
   | id | time | debtor | creditor | amount | rate | item |

   **history**（已結清歸檔）
   | id | record_time | clear_time | debtor | creditor | amount | rate | item |

   **config**（設定，key/value 形式，程式會自動補上找不到的 key）
   | key | value |

   目前會用到的 key：`cashier_channel_id`、`recovery_channel_id`、`notify_channel_id`（每日匯率／美股播報與每日提醒共用的頻道）、`treat_role_id`（有人請客時要 tag 的身分組 ID，`0`＝不 tag）、`jpy_report_enabled`（`on`/`off`，同時控制日幣與美金匯率播報）、`stock_report_enabled`（`on`/`off`）、`jpy_threshold`（數字，只影響日幣的划算文案）、`time_storage`（機器人自己寫入的記號，代表這份試算表的時間已經是台灣時間，**請勿刪除**）

   **members**（成員）
   | name | discord_id |

   **triggers**（觸發詞）
   | id | keyword | response_text | image_url | mention_name | match_type | reply_type | probability |

   **reminders**（每日提醒）
   | id | content | mention_name | hour | minute | created_by | created_by_name |

   **purchases**（代購）
   | id | status | agent_discord_id | agent_display_name | creation_source | requester_discord_id | requester_display_name | requester_line_id | item_description | image_url_1 | image_url_2 | image_url_3 | store_location | auto_approve_limit_jpy | confirm_required_above_jpy | spec_conditions | item_nature | notes | acknowledged_risk | created_by_discord_id | created_at | updated_at |

   **trips**（代購行程，同一位代購人同時只會有一列）
   | agent_discord_id | agent_display_name | itinerary_text | started_at |

   **trip_history**（行程結束時的委託歸檔，沒有任何指令會讀取這個分頁，只能自己打開試算表查）
   | id | status | agent_discord_id | agent_display_name | creation_source | requester_discord_id | requester_display_name | requester_line_id | item_description | image_url_1 | image_url_2 | image_url_3 | store_location | auto_approve_limit_jpy | confirm_required_above_jpy | spec_conditions | item_nature | notes | acknowledged_risk | created_by_discord_id | created_at | updated_at | trip_itinerary_text | trip_started_at | archived_at |

   **guilds**（其他伺服器的綁定資料。只存在主試算表，有伺服器綁定時機器人會自動建立，不需要手動新增）
   | guild_id | guild_name | sheet_id | service_account_email | credentials_encrypted | bound_by | bound_at |

   > 🕗 `expense`／`history` 的時間欄位一律是**台灣時間**。舊版存的是 UTC，新版第一次啟動時會自動把這兩個分頁的舊資料加 8 小時（每份試算表只做一次，做完會在 `config` 寫入 `time_storage` 記號）。升級前建議先在 Google 試算表「檔案 → 建立副本」留一份備份。

   > ⚠️ **隱私提醒**：`purchases`／`trips`／`trip_history` 分頁存的是委託人的物品、LINE ID 等私人資料，Discord 端已經做到「只有本人看得到」，但這只擋得住 Discord 介面——**任何被分享到這份試算表的 Google 帳號都能直接打開分頁看到全部內容**，不受 Discord 權限限制。目前設計假設這份試算表只有你（擁有者）＋機器人服務帳號能存取；如果之後把這份試算表共用給其他人（例如協助記帳），代購資料的隱私就會被繞過，屆時建議把這三個分頁移到另一份不共用給任何人的試算表。

5. 將試算表共用給服務帳號的 `client_email`（編輯者權限）
6. 將 JSON 金鑰內容以 base64 編碼：
   ```bash
   base64 -i credentials.json
   ```
   或 Windows PowerShell：
   ```powershell
   [Convert]::ToBase64String([IO.File]::ReadAllBytes("credentials.json"))
   ```

### 3. 取得 imgbb API Key（觸發詞圖片上傳用）

1. 前往 [imgbb.com](https://imgbb.com) 註冊帳號
2. 進入 [API 頁面](https://api.imgbb.com) 取得 API Key

### 4. 環境變數

在專案根目錄建立 `.env`：

```env
DISCORD_TOKEN=你的Bot Token
GOOGLE_SHEET_ID=你的試算表ID
GOOGLE_CREDENTIALS_BASE64=你的base64編碼金鑰
IMGBB_API_KEY=你的imgbb API Key
HOME_GUILD_ID=你自己伺服器的ID
GUILD_SECRET_KEY=一串夠長的亂碼
```

`HOME_GUILD_ID` 指定哪一個伺服器使用上面這份試算表（主伺服器）。沒設定時機器人會用預設播報頻道所在的伺服器來判斷，建議明確設定。

`GUILD_SECRET_KEY` 用來加密其他伺服器交給機器人保管的金鑰，**沒設定就代表不開放其他伺服器綁定**。至少 16 個字，可以這樣產生：

```bash
python -c "import secrets; print(secrets.token_urlsafe(32))"
```

設定後不要更換，換了之後已綁定的伺服器都要重新綁定。詳見下方「讓其他伺服器使用」。

**請勿 commit `.env` 或 `credentials.json`，兩者已加入 `.gitignore`。**

### 5. 啟動

```bash
python bot.py
```

### 6. Discord 初始設定

機器人上線後，以管理員身份依序執行：

```
/管理者工具    # 選「成員管理」新增成員並設定對應的 Discord ID
/管理者工具    # 選「設定頻道」設定收銀台、餐盤回收區、每日播報／提醒三個頻道 ID
```

## 觸發詞系統

`/新增觸發詞` 採兩段式 UI：

**第一段：選擇觸發與回覆方式**
- 可選填 `image` 附件（圖片自動上傳至 imgbb 取得永久連結）
- Bot 回應下拉選單，選擇觸發方式與回覆方式

**第二段：Modal 表單**
- 觸發關鍵詞
- 回覆文字（用 `<>` 分隔可設定多個隨機選項，例如：`彥丞道歉<>彰化人不行<>又是你`）
- 要 @ 的成員名（選填）
- 觸發機率 0–100（同關鍵詞多筆時作為競爭權重）

### 觸發方式

| 類型 | 說明 | 範例關鍵詞 | 觸發 | 不觸發 |
|------|------|-----------|------|--------|
| 包含 | 訊息中包含關鍵詞（不分大小寫） | `彰化` | 「路過彰化」 | — |
| 完全相符 | 整則訊息完全等於關鍵詞 | `彰化` | 「彰化」 | 「路過彰化」 |
| 正則 | 正規表達式（re.IGNORECASE） | `彰.+人` | 「彰化人」 | 「彰化」 |

正則會對每一則訊息執行，寫壞了會卡死整個機器人，所以新增／編輯時會檢查：語法要正確、長度 200 字以內、不能有巢狀量詞（例如 `(a+)+`）。沒通過檢查的正則（包含直接在試算表裡填的）不會觸發，`/管理觸發詞` 的列表會標出「⚠️ 這筆不會觸發」與原因。關鍵詞是空白的觸發詞同樣不會觸發。

### 回覆方式

| 類型 | 說明 |
|------|------|
| 新訊息 | Bot 發一則獨立訊息 |
| 回覆該則 | Bot 引用原訊息並回覆（有箭頭） |

### 編輯與刪除

`/管理觸發詞` 列表中的「編輯 / 刪除觸發詞」按鈕選單已整合成一套流程：選一筆觸發詞後，會再跳出「✏️ 編輯」「🗑️ 刪除」兩個選項。編輯會沿用新增時的兩段式 UI（Select 預選目前的觸發／回覆方式，Modal 預填目前的關鍵詞、回覆文字、@ 對象、機率）。新增因為需要直接上傳圖片附件，維持獨立的 `/新增觸發詞` 指令。

## 代購系統

取代原本各代購人自己維護的 Google 表單／試算表，改在 Discord 內用指令委託與查詢，圖片直接上傳、馬上看得到，不用再點連結。

**隱私原則：一筆委託只有指定的代購人本人、以及送出委託的委託人本人看得到、能操作，連伺服器管理員都看不到內容、也不能代為操作。** 管理員唯一能做的例外是 `/代購強制刪除`，而且那支指令刻意設計成看不到物品等任何內容（見下方）。這個原則只適用於 Discord 介面內；Google 試算表本身的存取權限不受 Discord 管控，詳見上方「設定 Google Sheets API」段落的隱私提醒。

### `/代購委託`

只有一個指令，不分「幫自己委託」或「幫別人登記」兩支指令——由 `委託人稱呼` 是否填寫決定：

- **留空**：委託是幫自己的，身份自動帶入你的 Discord 名稱。
- **填寫**：委託是幫填寫的那個人（不論在不在群組內、不論是誰按的指令），例如代購人幫群組外的朋友登記，或成員幫另一位成員代填。

流程：先選定 `代購人`（必填）。送出後 Bot 會顯示該代購人目前登記的行程（見下方「代購行程」；**沒登記行程也一樣能委託**，Bot 只會提醒你自行確認對方方不方便，不會擋下），再接一則提醒「不一定能買到」的確認訊息，按下「✅ 我了解，繼續填寫」後進入兩段式 Modal：

**第一段**：物品網址／圖片說明／名稱、在哪裡買得到、尺寸規格顏色條件（選填）、物品性質（選填）。送出後 Bot 會回一則「請按下方按鈕繼續填寫第二段」，**按「下一步 →」才會跳出第二段**（Discord 的 Modal 不能在送出時直接連鎖跳出下一個 Modal，中間一定要隔一次按鈕點擊）。
**第二段**：不需確認可直接買的金額上限（日圓，選填）、超過多少日圓需先確認（選填）、LINE ID（選填，附註說明：代購人如果已經知道你的 LINE 可以留白，不知道的話請填讓對方能聯絡你）、備註（選填）

**兩段 Modal 送出後才輪到附圖**：Bot 會請你直接私訊（DM）機器人本人並附上圖片，最多 3 張，90 秒內傳送即可（可以分好幾則訊息傳，收到就會加 ✅ 反應），電腦版可以截圖後直接 Ctrl+V 貼上、手機版可以選相簿，不需要圖片就按「🚀 不用附圖，直接送出」。之所以改成私訊而不是指令參數或頻道貼圖，是因為 Discord 的指令附件欄位在電腦版沒辦法貼上剪貼簿截圖（只能點開檔案總管選檔案），私訊機器人則手機、電腦都能用同一種方式操作，而且私訊本來就是只有你跟機器人看得到，不會像貼在頻道裡那樣被路過的人看到。

送出後會用 Embed 卡片（含圖片）顯示委託內容，只有本人看得到。

### `/代購進度`（唯一的查詢入口，代購人視角 + 委託人視角合併）

不管是「別人請你買什麼」還是「你請別人買什麼」，都從這一支指令進去，不用記兩個指令名稱。指令會同時算出你的兩種身份各有幾筆：

- **只有一種身份有紀錄**：直接跳進該身份對應的清單，不會多問。
- **兩種身份都有紀錄**：先跳出「📦 你同時有兩種代購紀錄，想先看哪一種？」，兩個按鈕「🛍️ 別人請我買的」「📋 我請別人買的」，選一個再進對應清單。
- **兩種都沒有**：回「📭 你目前沒有任何代購相關紀錄。」

兩種清單都是用下拉選單瀏覽（超過 25 筆會自動分頁），選一筆後顯示同一張 Embed 詳情卡片（含圖片）。卡片欄位順序特意把最重要的資訊放前面：狀態（買到了沒）→ 委託人（誰委託的，含 LINE）→ 物品 → 尺寸規格條件 → 購買地點（**如果委託人貼的是 Google Map 等網址，這裡會自動變成可以直接點開的連結，連結文字會標出實際網域，例如「📍 開啟連結（maps.app.goo.gl）」，點之前看得到會連去哪裡**）→ 金額門檻，代購人、備註等次要資訊放在卡片下半部。

**🛍️ 別人請我買的（代購人視角）**：多張圖可用「🖼️ 換圖」切換，並提供狀態按鈕：

| 按鈕 | 狀態 |
|------|------|
| 🛍️ 已購買 | `purchased` |
| ❌ 無法買到 | `cancelled` |
| 🗑️ 刪除紀錄 | 直接刪除該筆委託 |

委託建立時預設狀態一律是「⏳ 待處理」（`pending`），狀態需要代購人自行依現場狀況判斷後手動點選「已購買」或「無法買到」，Bot 不會自動變更狀態。只有該委託指定的代購人本人能操作狀態按鈕。

**📋 我請別人買的（委託人視角）**：提供：

- **✏️ 修改**：跳出跟 `/代購委託` 一樣的兩段式 Modal（物品資訊 → 按鈕 → 金額與聯絡方式），預填目前的內容，改完直接覆蓋。改變心意或填錯字都可以用這個修正，**目前不支援透過這裡重新上傳圖片**，圖片要換的話建議刪除重新委託一次。
- **🗑️ 刪除委託**：委託人自己反悔，直接刪掉。

只有 `creation_source` 是「自助委託」（`委託人稱呼` 留空）的才會出現在這裡，因為系統只在這個情況下知道委託人的 Discord 身份；被別人代填登記的委託沒有對應的 Discord 帳號可以核對，本來就無法透過這支指令自助查詢或修改。

（如果你自己委託給自己，這筆紀錄會同時算進兩種身份，兩邊都看得到，屬於正常現象。）

### `/代購行程`

代購人出發前可以登記「大致行程」（例如：`7/20-7/25 大阪、京都`），讓委託人在 `/代購委託` 選定代購人之後，順便看到這段說明，評估要不要委託他買東西。下拉選單兩個選項：

- **📍 開始／更新行程**：跳出 Modal 填一段行程說明；已有行程時再次執行會帶出目前內容供修改。**每次開始或更新都會把 `started_at` 更新成當下的台灣時間**，代表這是「最近一次編輯行程的時間」，不是永遠固定在第一次設定的時間。
- **🏁 結束行程並清空這趟所有委託**：會先顯示目前行程內容與待處理的委託筆數，需要再按一次「⚠️ 確認結束並清空，無法復原」才會真的執行。確認後這趟**不分狀態（含已購買）的所有委託會整批複製進 `trip_history` 分頁歸檔**（多存 3 個欄位：這趟的行程說明、行程開始時間、歸檔時間），接著才從 `purchases` 分頁移除，同時清空行程說明。歸檔後這些委託**不會再出現在 `/代購進度` 的任何一種身份視角裡**，只有直接打開 Google 試算表看 `trip_history` 分頁才找得到——平常沒事不會去看，只有真的需要對帳或查證時才會用到。

### `/代購強制刪除`

給「代購人已經離開群組、或委託卡住沒人處理」等例外狀況用的管理員安全閥。因為代購人可能已經不在群組裡了，Discord 的成員選單根本選不到人，所以改成**輸入代購人的 Discord 使用者 ID**（純數字，開發者模式下右鍵任何一則這個人的訊息或提及都能複製到，即使對方已離開伺服器也一樣能用）。畫面上只會顯示這個 ID、目前有幾筆委託、以及嘗試查到的暱稱（查不到就顯示「無法取得使用者名稱」），**不會顯示物品名稱、圖片、LINE ID 等任何委託內容**，需要再按一次確認才會真的執行。這個指令會**直接刪除該代購人名下所有委託，不會歸檔到 `trip_history`**，跟 `/代購行程 → 結束行程` 的正常流程不同，純粹是緊急救援用。平常代購人自己刪除委託請直接用 `/代購進度 → 別人請我買的` 裡的「🗑️ 刪除紀錄」，不需要動用這支指令。

## 年度回顧

`/年度回顧 [年份]` 統計某一年度（留空＝今年至今）每一對有借貸往來的成員：
- 來往筆數
- 雙向金額（A 欠 B / B 欠 A 各自加總）
- 該年度該配對中單筆金額最大的一筆交易（含日期、項目名稱）
- 年度結束後的淨餘額

會同時讀取 `expense`（尚未結清）與 `history`（已結清歸檔）兩張表做聯集，所以不管那筆帳目後來有沒有 `/結清` 過都算得到。時間判斷會校正成台灣時區再取年份，避免午夜前後的交易被歸到錯的一年。

## 每日提醒

`/每日提醒` 用下拉選單整合三個功能：

- **➕ 新增每日提醒**：選擇提醒的小時（0–23）與分鐘（00/15/30/45），可選填要不要 tag 某位成員，最後在 Modal 填提醒內容
- **🗑️ 刪除每日提醒**：只列出自己建立的提醒（管理員會看到所有人的，可代刪）
- **⚙️ 播報設定**（管理員限定）：開關「每日匯率播報（日幣＋美金）」「美股播報」，並調整日幣划算門檻（原本寫死在程式碼的 0.198，現在改存進 `config` 分頁的 `jpy_threshold`）

每分鐘會檢查一次是否有提醒到期，到期時發送到跟每日匯率／美股播報相同的頻道，可透過 `/管理者工具 → 設定頻道` 調整（`notify_channel_id`）。

## 自動任務

- **每日播報**：每天台灣時間 09:00 固定發送（不再像以前只有匯率低於門檻才發）：
  - 日幣匯率（低於 `jpy_threshold` 才會多附加碼文案）
  - 美金匯率（`1 USD = ? TWD`，跟日幣共用同一個「匯率播報」開關，沒有划算門檻）
  - 昨夜美股收盤：道瓊、那斯達克、標普500、費城半導體，任一指數單日漲跌超過 3% 會附上對應的吐槽文字
  - 匯率、美股兩個區塊都可以透過 `/每日提醒 → 播報設定` 個別關閉；查詢失敗時只有那一項會顯示「查詢失敗」（日幣、美金各自獨立），不會讓整則播報消失
- **每日提醒**：使用者自訂的每日固定時間提醒，見上方「每日提醒」章節
- **請客偵測**：訊息包含「我請大家」「我請客」「請大家吃」時，自動 tag 指定的身分組並釘選訊息（身分組在 `/管理者工具 → 設定頻道` 指定；主伺服器沒指定時用程式裡的預設值，其他伺服器沒指定就只釘選、不 tag）

## 讓其他伺服器使用（多伺服器）

這個機器人可以同時待在很多個伺服器裡，但**每個伺服器的資料都存在自己的 Google 試算表**，用自己的服務帳號金鑰讀寫（所以用的是各自的 Google API 額度）。伺服器之間完全看不到彼此的帳目、成員、觸發詞、提醒、代購與頻道設定。

- **主伺服器**（機器人擁有者的伺服器）：使用環境變數裡的 `GOOGLE_SHEET_ID` 與 `GOOGLE_CREDENTIALS_BASE64`，跟以前一樣。
- **其他伺服器**：機器人被邀進去之後什麼指令都不能用，直到那個伺服器的管理員完成綁定。

### 機器人擁有者要做的事（只需要做一次）

1. Developer Portal → Bot 的 **Public Bot** 保持開啟，把邀請連結給對方
2. 在 Render 環境變數設定 `HOME_GUILD_ID`（你自己伺服器的 ID）與 `GUILD_SECRET_KEY`（用來加密對方的金鑰；沒設定就代表不開放綁定）

### 其他伺服器的管理員要做的事

執行 `/管理者工具`，機器人會顯示完整的步驟：

1. 開一份空白的 Google 試算表
2. 到 Google Cloud Console 建立專案、啟用 Google Sheets API、建立服務帳號並下載 JSON 金鑰
3. 把試算表共用給金鑰裡的 `client_email`（編輯者）
4. 按「開始綁定」，貼上試算表網址與整份 JSON 金鑰

綁定成功後機器人會自動建立所有需要的分頁，接著再用 `/管理者工具` 新增成員、設定頻道就能開始使用。之後可以從 `/管理者工具 → 設定試算表` 更換試算表／金鑰，或解除綁定（機器人會刪除保管的金鑰，對方試算表裡的資料不會被動到）。

### 需要知道的事

- 對方的金鑰會交給機器人保管：以 `GUILD_SECRET_KEY` 加密後存在主試算表的 `guilds` 分頁。也就是說，**機器人擁有者技術上有能力讀寫對方的那份試算表**。請讓對方使用專門為這個機器人建立、而且只共用了那一份試算表的服務帳號。
- 一份試算表只能綁定一個伺服器；主試算表不能被其他伺服器綁定。
- 所有伺服器共用同一台 Render 主機。Google Sheets 的讀寫是同步的，某個伺服器的試算表回應很慢時，其他伺服器的指令也會跟著慢（每次呼叫最多等 20 秒）。
- 私訊機器人下指令只開放給主伺服器的成員（用的是主伺服器的資料）；其他伺服器的成員請在伺服器裡下指令。
- `GUILD_SECRET_KEY` 換掉之後，已綁定的伺服器都要重新綁定。

## 安全機制

- **每個伺服器只碰得到自己的資料**：每個指令、按鈕、表單、訊息都會先確定來自哪個伺服器，之後的資料讀寫只會用那個伺服器的試算表；判斷不出是哪個伺服器時會直接報錯，不會退回去用主試算表。
- **沒綁定就不能用**：還沒綁定試算表的伺服器只有 `/管理者工具`（綁定引導）有反應，那裡的訊息也不會觸發觸發詞。
- **主伺服器要明確**：`HOME_GUILD_ID` 決定哪個伺服器使用主試算表。沒設定時用預設播報頻道所在的伺服器判斷；判斷不出來就不開放給任何伺服器。啟動時 log 會印出 `🏠 主伺服器：…` 以及每個伺服器的狀態，部署後請確認一次。
- **頻道設定檢查**：收銀台、餐盤回收區、播報頻道只能設成同一個伺服器裡的頻道；設定值指向其他伺服器的頻道時，機器人會當作找不到，不會發送也不會清空。
- **金鑰處理**：別人貼進來的金鑰只保留登入需要的欄位，連線位址一律改用 Google 官方網址；金鑰加密儲存，不會出現在任何回覆或 log 裡。

## 部署至 Render（Web Service 免費方案）

本機器人內建 Flask 輕量伺服器（`keep_alive()`），搭配 [UptimeRobot](https://uptimerobot.com) 防止 Render 免費方案休眠。

1. 將程式碼推上 GitHub（確認敏感檔案已被 gitignore）
2. 在 [Render](https://render.com) 建立 **Web Service**，連結 GitHub Repository
3. Start Command：
   ```
   python bot.py
   ```
4. 在 Render Dashboard → **Environment** 設定以下環境變數：

| Key | Value |
|-----|-------|
| `DISCORD_TOKEN` | Bot Token |
| `GOOGLE_SHEET_ID` | Google 試算表 ID |
| `GOOGLE_CREDENTIALS_BASE64` | base64 編碼的服務帳號 JSON |
| `IMGBB_API_KEY` | imgbb API Key |
| `HOME_GUILD_ID` | （建議設定）主伺服器的 ID：只有這個伺服器使用上面那份試算表 |
| `GUILD_SECRET_KEY` | （要開放其他伺服器綁定才需要）加密其他伺服器金鑰用的亂碼，至少 16 個字 |

5. 部署完成後在 UptimeRobot 新增 HTTP monitor，每 5–10 分鐘 ping 一次 Render 提供的 URL

## 注意事項

- 斜線指令同步最多需等待數分鐘
- 分帳金額採無條件進位（`math.ceil()`），實際總額可能略高於原始金額
- `/結清` 前需確認雙方間的帳目方向一致；否則會出現提示
- `/查帳` 與 `/藍白` 的 @ 功能需先透過 `/管理者工具 → 成員管理 → 設定對應` 完成 Discord ID 綁定
- 觸發詞機率欄位僅在**同關鍵詞有多筆競爭時**作為權重使用；單筆觸發詞永遠 100% 觸發
- 美股資料來源（Yahoo Finance chart API）為非官方介面，沒有正式文件保證，未來若格式異動可能導致查詢失敗（僅該指數顯示「查詢失敗」，不影響匯率或其他指數）
- 每日提醒的時間精確度為 15 分鐘一格（00/15/30/45），無法設定到分鐘級的任意數字
- 一般成員在 `/每日提醒 → 刪除` 只看得到自己建立的提醒；`播報設定` 僅限管理員使用
- 代購相關清單一律以 ephemeral（僅本人可見）訊息呈現，不會公開發到頻道，也不對管理員開放例外（`/代購強制刪除` 除外，且該指令刻意看不到內容）
- 代購資料的隱私僅止於 Discord 介面層級；能打開該份 Google 試算表的任何人都能繞過上述限制直接看到原始資料，務必確認這份試算表沒有共用給其他人（見「設定 Google Sheets API」段落）
- `/代購委託` 的圖片改成送出兩段 Modal 後私訊機器人附圖，最多 3 張、90 秒沒傳就視為不附圖繼續送出；不再是指令參數，也不會出現在頻道訊息裡
- `/代購行程 → 結束行程` 會把該代購人**當下所有**委託（不分狀態）歸檔到 `trip_history` 分頁後從 `purchases` 移除，之後任何指令都查不到，只能直接打開試算表看
- `/代購進度` 已經合併了代購人視角跟委託人視角，不再有獨立的「我的代購清單」指令；「我請別人買的」那一半只查得到「自助委託」（`委託人稱呼` 留空）的紀錄，被別人代填登記的委託沒有對應 Discord 身份，本來就無法自助查詢
- `/重新整理` 會一併清除成員、設定、觸發詞、代購、行程快取，全部重新從試算表讀取
- `/結清` 只會刪掉這次結清的那幾列（單一 API 呼叫），不會動到其他人的帳目；記帳時間與結清時間在試算表裡一律存台灣時間
- 代購附圖只接受圖片檔、單張 10 MB 以內；上傳失敗的訊息會被加上 ⚠️ 反應而不是 ✅
